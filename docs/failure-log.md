## B-2. rigor 훅 인프라에서 관찰 (2026-08-31)

게이트 자체가 실패하는 층. 판정 규율(A·B절)과 달리 여기서는 **무증상**이 특징이다 —
훅은 정상 종료하고 로그도 남지 않으므로, 게이트가 돈다는 착각만 남는다.

| # | 유형 | 내용 | 처리 |
|---|---|---|---|
| 26 | **훅 무증상 미실행 (안전 사고)** | Windows에서 셔뱅 `python3`가 Microsoft Store 앱 실행 별칭 스텁으로 잡혀 "Python was not found" 출력 후 **exit 0** — Claude Code는 정상 통과로 읽고, 게이트가 한 번도 돌지 않은 채 모든 산출물이 통과됐다 | `hooks/run-rigor.sh` 런처: 인터프리터를 이름이 아니라 동작(`print(42)`)으로 고름 |
| 27 | 인코딩에 의한 전면 skip | `json.load(sys.stdin)`이 로케일(cp949)로 열려 한글 산출물이 깨지고 `ARTIFACT_MARKERS` 전부 불일치 → 모든 입력 `skip`. 회귀 스위트의 block 기대 8건이 전원 pass로 뒤집혀 발견 | stdin/stdout을 UTF-8로 명시 처리, 스위트도 `encoding="utf-8"` |
| 28 | 경고의 휘발 | 반송 상한 도달 시 남기던 `systemMessage`는 발신자 화면에서 사라진다. 정작 보호 대상은 그 문서를 건네받는 동료 | D3: 최종 반송에서 산출물 머리말에 '공증 실패' 배너 부착 요구 + 로그 기계 판독 필드 |
| 29 | 정직 처벌(재발 위험) | 배너를 붙이면 배너 안의 문장이 다시 주장으로 검출된다 — 런 F·H와 같은 구조 | 배너와 그 목록을 검사 대상에서 제외. 설계 원칙 절로 승격(`hooks/rigor-spec.md`) |

**26·27번의 공통점**: 둘 다 "게이트가 무력해졌다"인데 증상이 **통과**다. 오탐은 시끄럽게
드러나지만 미실행은 조용하다. 회귀 스위트가 두 번 다 발견자였다 — 스위트를 실제 사용
플랫폼에서 돌리는 것 자체가 검증 항목이다.
