# Executor — 판정을 건넬 수 있는 문서로

> 유언 집행인: 고인(아이디어)의 유산을 유언장(작업 지시서)대로 분배한다 —
> 커버된 자산은 기존 도구에게, 남은 gap은 상속인(동료)에게.

> **실행 모델 요구사항 — 상위 모델 권장.**
> 입력이 되는 coroner 판정문의 신뢰도가 곧 이 지시서의 신뢰도다. 하위 티어 모델이 만든
> 판정문(검증 없는 "해결", 위조된 출처 태그)을 그대로 이슈로 옮기면 오류가 그대로 상속된다.
> 근거: `docs/run-ledger.md`, coroner SKILL.md 상단 고지.

## 전제

이 스킬의 입력은 **coroner(build-or-use) 판정문**이다 (capability 분해표 + coverage 상태 + 근거).
판정문이 대화에 없으면 지시서를 만들지 말고 build-or-use 판정을 먼저 수행하도록 안내한다.
판정 없이 지시서만 요구받은 경우, 이 문서의 모든 주장은 검증되지 않았음을 머리말에 명시한다.

## 핵심 규칙 — 새 주장 발명 금지

지시서는 판정문의 **재배열이지 증보가 아니다.** 지시서의 모든 사실 주장(도구의 존재, 기능,
가격, 제약)은 다음 중 하나여야 한다:
1. 원 판정문에 이미 존재 (provenance 태그 승계)
2. 이 단계에서 새로 검색해 확인 ([WEB] 태그 + 실제 검색 실행)

지시서 작성 중 "아마 이럴 것"이 필요해지면 [INFERENCE]로 표기하거나 "확인 필요" 항목으로
내린다. 검색 없이 [WEB]을 붙이는 것, 확인 안 한 문서를 확인했다고 쓰는 것은 최악의 위반이다.
근거 표시가 없는 주장을 지적받으면(반송), 변명하지 말고 실제 검색을 실행해 해당 부분만 수정한다.

## 출력 1 — 이원 지시서 (기본)

**머리말**: 원 아이디어 한 줄, 판정 등급, 판정 일자, "이 문서의 모든 주장에는 출처 표시가 있으며,
[INFERENCE] 표시 항목은 검증되지 않았다"는 안내.

**A부 — 설정 가이드** (coverage "해결/부분 해결" 항목):
항목별로 [무엇을 쓴다 | 설정 방법 요약 | 근거 링크(원 판정 태그 승계) | 한계(부분 해결인 경우)].

**B부 — 이슈 목록** (coverage "미해결" = 만들 것):
이슈마다 다음 필드를 강제한다.
- 제목 (동사로 시작)
- 배경: 왜 기존 것으로 안 되는지 — 원 판정의 gap 근거를 인용
- 수용 기준: 완료를 판정할 수 있는 관찰 가능한 조건 2~3개
- **선행 조건**: A부의 어느 설정 항목이 먼저 완료되어야 하는지 (없으면 "없음" 명시)
- 근거: provenance 태그
- 확인 필요: 착수 전 검증할 가정이 있으면 명시

"확인 불가/사용 테스트 필요/개발로 해결 불가" 항목은 이슈로 만들지 않는다 — **C부 미결 목록**으로
분리하고 각각의 해소 방법(재검색어, 사용 테스트 설계, 구조적 한계 설명)을 붙인다.

## 출력 2 — Taskmaster 호환 PRD (요청 시)

사용자가 태스크 분해·종속성 그래프까지 원하면, 자체 계산하지 말고 claude-task-master의
parse-prd가 소화하는 종속성 인지형 PRD로 변환 출력한다: 모듈 경계를 명시하고, B부 이슈를
섹션으로, 선행 조건을 명시적 의존 관계 서술로 옮긴다. 문서 말미에 사용법을 한 줄 안내:
`task-master parse-prd <파일>` (검증: `validate-dependencies`). 종속성 검증·위상 정렬·
next task 추천은 Taskmaster의 일이다 — 이 스킬이 흉내 내지 않는다.

## 출력 3 — 내보내기 안내 (요청 시)

연결된 이슈 트래커 MCP(Linear, Jira 등)가 있으면 B부 이슈를 생성할 수 있음을 알리고,
사용자 승인 후 이슈 본문에 근거 표시를 포함해 생성한다. 승인 없이 생성하지 않는다.

## 금지

- 종속성 그래프·일정·간트 계산 (Taskmaster/트래커 위임)
- 공수·기간 추정 ("2~3일" 류 — build-or-use와 동일한 이유로 금지)
- 시장성·수익 분석 (범위 밖)
- 원 판정 뒤집기 — 지시서 단계에서 판정 등급을 바꾸고 싶어지면, 바꾸지 말고
  "판정 재검토 필요" 사유를 기록해 사용자에게 돌려준다

## 한계 고지 (문서에 포함할 것)

provenance 태그는 자기 보고이며, 별도의 검증 게이트(주장-로그 대조) 없이는 신뢰 보증이
아니다. 이 지시서를 받는 사람은 [INFERENCE]·"확인 필요" 항목을 착수 전에 직접 확인해야 한다.
