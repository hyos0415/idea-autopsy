# rigor — 주장-로그 대조 게이트 (사양, 미구현)

## 왜 훅인가
Δ 실험 실측: 지침(스킬)은 하위 티어에서 위조된다 — 검색 없이 [WEB] 태그를 붙이고,
하지 않은 확인을 했다고 쓴다. 강제는 모델 바깥의 코드여야 하며, Claude Code에서 그 자리는
훅(hook)이다: "훅은 반드시 일어나야 하는 동작, 스킬은 따라야 할 지침."

## 동작 사양 (구현 시)
1. 트리거: coroner/executor 산출물이 완성되는 시점 (Stop 또는 응답 후 이벤트)
2. 검사: 산출물 텍스트에서 다음 패턴 추출 — [WEB]/[FILE] 태그, "확인했다/검증했다",
   구체 URL·수치 인용, "없다/불가/미지원" 단정문
3. 대조: 세션 로그의 실제 도구 호출(WebSearch/WebFetch/Read)과 시간순 매칭
4. 판정: 대응 호출 없는 주장 발견 시 — 차단하고 정형 반송문 주입:
   "다음 주장에 대응하는 검색 실행 기록이 없습니다: '[문장]'. 실제로 검색을 실행하고
   해당 부분만 수정해 다시 제출해주세요." (힌트 금지, 최대 2회, 이후 '교정 불가' 플래그)
5. 원칙: 탐색량 임계 없음 — 잡는 것은 "적게 한 것"이 아니라 "안 했는데 했다고 한 것"
   (Opus low-effort 프로브 실측: 정직한 축소는 통과 대상)

## 검증 체크리스트 (구현 후, 배포 전 필수)
- [ ] claude --plugin-dir ./plugin 로컬 설치, /plugin Errors 탭 확인
- [ ] 위조 재현 케이스(Δ rep1 S1 입력)에서 반송이 실제 발생하는가
- [ ] 깨끗한 산출물(Opus 런 수준)이 오탐 없이 통과하는가 (오탐률 <20%)
- [ ] 반송 후 모델이 실제 검색을 실행하는가 vs 위조를 정교화하는가 (둘 다 기록)
