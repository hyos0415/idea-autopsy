# idea-autopsy

> **"이 아이디어는 죽었습니다. 대신 시신에서 쓸 장기들입니다."**
>
> — 만들기 전에 먼저 부검하는 Claude 스킬 3종 (build or use?)

새 아이디어가 생기면 개발에 들어가기 전에 검시부터 합니다. 현재의 AI 기능·기존 스킬·MCP·
오픈소스·기존 제품만으로 어디까지 해결되는지를 검색·검증 규율에 따라 조사하고, 사망 원인을
근거와 함께 규명합니다. 다만 이 부검소의 원칙은 하나입니다 — **판정의 목적은 개발의 중단이
아니라 중복의 중단이며, 유족은 기각문이 아니라 장기기증 카드를 들고 떠납니다.**

## 검시소 구성원

| 스킬 | 직책 | 하는 일 |
|---|---|---|
| [`coroner`](skills/coroner/) | 검시관 | 아이디어 판별 — capability 분해 → 4계층 탐색(AI native / 스킬·플러그인 / MCP / OSS·제품) → 검증 → **사망진단서** 발급 (Just Use AI / Configure / Build a Skill / Build a Custom Product). 사인란에는 근거 링크가 붙는다 |
| [`executor`](skills/executor/) | 유언 집행인 | 판정문 → **유언장(작업 지시서)** — 커버된 유산은 기존 도구에게(설정 가이드), 남은 gap은 상속인(동료)에게(이슈 단위 + 선행 조건 + 출처 표시). Taskmaster 호환 출력 |
| [`design-coroner`](skills/design-coroner/) | 디자인 검시관 | 디자인 시스템·컴포넌트 전담 — Adopt / Adapt / Create 판정 |
| `rigor` (사양만, [plugin/](plugin/)) | 사후경직 | 판정문의 주장([WEB] 태그·"확인했다"·"없다")을 실제 도구 호출 로그와 대조하는 검증 게이트 — 물렁한 주장을 걷어내고 굳은 사실만 남긴다. **미구현·미검증** (아래 참조) |

부수 출력: **장기기증 카드** — "만들지 마" 판정 시에도 발견물에서 차용할 자산(아키텍처,
분류 체계, 패턴)을 목록으로 동봉합니다.

## 설치 (투트랙)

- **채팅(claude.ai / 데스크탑) — 누구나**: 각 스킬 폴더의 `SKILL.md`를 스킬로 등록하거나,
  전문을 대화 첫 메시지에 붙여넣고 아이디어를 한 문장으로 입력
- **Claude Code — 개발자**: plugin/ 은 실험 단계입니다 (아래 정직 고지)

## 이 레포 자신의 검시 결과 (자기 부검)

이 스킬 패밀리도 자기 절차로 검시받았습니다. 소견: **인접물 실존** — 코드를 쓰기 전에 기존
해결책을 검색·비교하는 "Don't Reinvent the Wheel" 계열 스킬(programming-advisor), 아이디어의
시장성을 근거 우선으로 검증하는 /validate, 스킬 제작 전 prior-art 조사를 내장한 skill-creator류가
이미 있습니다. 본 검시소의 고유 지분은 심층부입니다: 4계층×4단계 판정 체계, 부재단정 차단
규율(검색 실패 ≠ 부재, 검색 없는 [WEB] 태그 = 위조), 사전 등록 실험 39런의 실측 근거, 그리고
판정→유언장→장기기증으로 이어지는 파이프라인. 판정: **Build a Skill 정당 (심층 gap 재작성)** —
겸허히, 이웃들과 같은 결론입니다.

### 이웃들과의 차이 (자기 검시 부속 문서)

| | programming-advisor | /validate | idea-autopsy |
|---|---|---|---|
| 묻는 질문 | 코드 짜기 전, 라이브러리 있나? | 이 아이디어, 팔리나? | **만들어야 하는 것 자체가 맞나?** |
| 탐색 범위 | npm·GitHub 패키지 | 시장 신호 | 4계층: AI native → 스킬·플러그인 → MCP → OSS·제품 |
| 출력 | 비교표 | 근거 리포트 | 4단계 판정 + 뒤집힘 조건 + 사망진단서 |
| "없을 때" 규율 | — | 추정 거부 (정신 유사) | 부재단정 차단 명문화 + 태그 정직 조항 |
| 규율의 검증 | — | — | **사전 등록 실험 39런 실측** |
| 기각 이후 | 끝 | 끝 | 장기기증 카드 + 유언장(executor) + 도메인 변형 |

층이 다릅니다: 이웃들은 "만든다"가 전제된 뒤의 도구고, 이 검시소의 판정 절반(Just Use AI /
Configure)은 코드 0줄로 끝나는 결론입니다. /validate와는 경쟁이 아니라 직렬 —
coroner가 "gap 실존"을 내면 그다음 "팔리나"를 /validate류가 이어받습니다.

## 왜 믿을 수 있나 — 실험으로 다듬어졌습니다

모든 버전업의 근거는 관찰된 실패입니다 ("Failure가 Requirement보다 먼저").

- **티어 실험** (사전 등록, 21런): 같은 스킬 문서로 Haiku 4.5는 실존 기능을 검색 없이 "없다"고
  단정(케이스 40%), Opus 5는 0% — 판정 규율은 모델 티어 의존적
- **Δ 실험** (10런): 문서를 강화하자 하위 티어는 규칙을 지키는 대신 **지킨 척**을 생성 —
  검색 시뮬레이션, 가짜 인용, 출처 태그 위조. rigor(주장-로그 대조)가 필요한 이유
- 상세: [실험 리포트](docs/experiment-report.md) · [실행 원장](docs/run-ledger.md) ·
  [실패 기록](docs/failure-log.md)

여담: 이 부검소가 낸 첫 사망진단서들의 명단에는 제작자 자신의 제품 아이디어가 세 건 올라
있습니다 (devtool, 이슈 대시보드, 전용 웹 UI — 사인: 기존 해결책 실존 및 정체성 불일치).
살아남은 장기가 이 레포입니다.

## plugin/ 에 대한 정직 고지

plugin/ 은 Claude Code 플러그인 스캐폴드(스킬 번들 + rigor 훅 사양)이며 **아직 설치·동작
검증을 거치지 않았습니다.** 이 검시소의 규율상, 검증하지 않은 것을 작동한다고 쓸 수 없습니다.
검증 절차는 [plugin/README.md](plugin/README.md)의 체크리스트를 따르세요
(`claude --plugin-dir ./plugin` 로컬 테스트부터). 검증 완료 후 이 문단은 삭제됩니다.

## 피드백 주시는 법 (환영합니다)

실제로 고민 중인 아이디어 하나를 검시받아 보시고, 이슈로 세 가지만:
1. 사망진단서(판정문) 전체 — 캡처 또는 텍스트
2. 판정에 동의하는지 한 줄
3. **이 문서를 동료에게 그대로 건넬 수 있겠는지** 한 줄

오진(부재단정)·어휘 불일치·환각 인용의 발견이 가장 값진 기여입니다 — failure log에 등재되고
다음 버전의 근거가 됩니다.
